## 5. 余白と大きさ（大きさが変わったときの調整）

### 大きさが変わったときの調整

スマホ・小さなブラウザの窓・横向きの低い画面・パネルで狭まった枠を、同じ考え方で扱う。画面でも部品でも、考え方は 1 つ:
**主役の領域をできるだけ大きく保ち、足りなくなったら周りから、戻しやすい手段から順に詰める。**

#### 領域に役割を付ける

画面・部品を作るときは、まず中の領域を 3 つに分け、主役の最小寸法を決める（文書・コメントに書く）。

| 役割 | 例（画面） | 例（部品） | 足りないとき |
|---|---|---|---|
| **主役** | 内容の枠（一覧・グラフ） | 名前・値・入力欄 | 最後まで残す。最小寸法（例: 幅 400px）を下回らせない |
| **周り** | 左メニュー・詳細パネル・ヘッダー・ツールバー | ボタンの並び・切り替え | 詰める → 畳む → 重ねる・別の画面へ |
| **補助** | KPI の帯・件数・前置きのラベル・飾りのアイコン | 補足（件数・単位）・先頭のアイコン | 消してよい（ただし 4 の「別の場所で得られる」を守る） |

#### 詰める順番（画面の骨組み）

主役の最小寸法が残らなくなったら、次の順に 1 段ずつ進める。前の段で足りるなら次に進まない。

1. **余白を詰める** — 外側の余白（`--shell-x` / `--shell-top` / `--shell-gap` / `--shell-bottom`）は窓の大きさに合わせてなめらかに縮む（上の「外側の余白」。区切りは要らない）。部品の中の余白は変えず、段組みの余白だけを詰める。
2. **周りの枠をコンパクトにする** — 同じ形のまま幅・高さを小さくする（詳細パネルは窓に合わせて 380 → 320px へなめらかに、ツールバーの上下の余白）。中身がはみ出さない範囲まで。
3. **補助の表示を落とす** — 補足・飾りを消し、ラベルをアイコンにする（下の「決め方」の 3）。高さが足りないときは帯ごと出さない（KPI の帯）。
4. **周りの枠を畳む** — 左メニューをアイコンだけの列に、検索と絞り込みを 1 つの段に、メニューと画面名を 1 つのボタンにまとめる。一時的に畳むとき（窓が狭いあいだだけ、など）は、利用者が覚えさせた設定を変えず、元に戻る条件をはっきりさせる。手で広げたらその操作を優先する。
5. **重ねる・画面を分ける** — それでも主役の最小寸法が残らないときだけ、周りの枠を主役の上に重ねる（左メニューの引き出し、詳細パネルの `Drawer`、スマホの下からのシート）か、別の画面・段に分ける。重ねると主役を操作しながら見られなくなるので、「開いたまま主役を操作できる」ことが大事な枠ほど、この段に入る幅を小さくする。

- 高さも同じ順で詰める（段組みの余白は高さに合わせて縮み、低い横長の画面ではさらにヘッダーの上下の余白を詰め → 検索欄もヘッダーの 1 段目に並べ → KPI の帯を出さない）。
- 区切りの値は、詰めた寸法から計算で出す。アプリの枠は `AppShell` の `sizes`（左メニュー・詳細パネルの幅、余白の下限、主役の最小幅 `mainMin`、パネルの取り分 `panel.share`）を渡すだけで、`shellLayout` が「パネルを詰める → 左メニューを畳む → 重ねる」を決める（区切りの幅は `shellBreakpoints` で確かめられる）。部品の中の区切りは、全部出したときに要る幅から計算し、式をコメントに書く。
- 新しい枠・帯を足すときは、この表のどの役割か、どの段で詰める・畳む・重ねるかを先に決める。既存の区切り（下の表）に乗せ、新しい区切りは作らない（作るなら表を直す）。

#### 決め方

1. **端末ではなく幅で決める** — 端末の種類で表示を出し分けない。端末で変えてよいのは操作の手がかりだけ（ツールチップは `(hover:hover)` の端末だけ、など）。
2. **入るなら大きく出す** — 区切りの幅で一律に隠さない。その部品が置かれた場所に実際に入るかで決める。
3. **落とす順番を先に決める** — 部品ごとに主役を 1 つ決め、ほかを大事でない順に落とす。主役を省略記号で詰めるのは最後。
   1. 補足を消す（件数・単位・前置きのラベル）
   2. 飾りを消す（ロゴ・先頭のアイコン）
   3. 余白を詰める（ボタンの左右の余白。`Segmented` の `dense`）
   4. ラベルを短くする（同じ意味の短い語。`Segmented` の選択肢の `short`。読み上げの名前も短い語になるので、意味が通る語にする）
   5. ラベルをアイコンにする（`aria-label` と `data-tip` を付ける）
   6. まとめる（個別の値を「N 件」にする、メニューと画面名を 1 つのボタンにする）
   7. 主役を省略記号で詰める
   - 部品の中で、主役に `data-fit="main"`、落としてよいものに `data-fit="extra"` を付ける（`Select` のボタン）。監査が「主役を詰めているのに extra が見えている」を拾う。
   - **詰め方は部品が持ち、どれを使うかは置き場所が決める**。部品は詰めた形を修飾（props）で持つ（`Segmented` の `hideCounts` / `fill` / `dense` / `short`、`MonthStepper` の `hideMeta`、`Select` の `fit`）。帯のように部品を並べるところでは、部品をまたいだ順番を `useFitStep`（段階ごとの見えない写しを測り、入る最初の段階を選ぶ）で 1 つに決め、修飾で部品に渡す。画面の CSS で部品の中（余白・件数・補足）を上書きしない（`ignite check` が警告し、新しく足した行は止める）。
4. **消したものは別の場所で得られるようにする** — どこでも得られなくなるものは消さず、段を足す。
5. **関係するものは同じ段に置き、まとまりで折り返す** — 付随するものは離さない。1 つだけを次の段に落とさない。
6. **項目の間に空きを作らない** — 伸びて意味のある部品（入力欄・切り替え）だけが残りの幅を埋める。並べる項目は左詰めにし、余りは段の右端にまとめる。
7. **横にはみ出さない、選ぶときは省略しない** — ページを横にスクロールさせない（中の表・一覧の横スクロールはよい）。プルダウンの選択肢は省略しない。
8. **切り替わりはなめらかに** — 出し入れは中身の実際の幅でアニメーションさせる。動かすのは操作したときだけで、窓の幅が区切りをまたいで形が変わるときは動かさずに最後の姿で出す。

| 何で決まるか | 使うもの |
|---|---|
| 画面の骨組み（左メニュー・パネル・ヘッダーの段組み） | `AppShell` と `shellLayout`。★ の区切りは寸法から計算し、ほかは ① の `shell.css` のメディアクエリ（下の表の値だけ。`ignite check` が `@media`・`matchMedia` の値を検査する） |
| 部品の置き場所の幅 | コンテナクエリ（`container-type: inline-size` と `@container`）。区切りは「全部出したときに要る幅」にし、理由をコメントに書く |
| 中身の長さ | 実際に測る（`ResizeObserver` で幅を見て、補足から順に隠し直す。`Select` の `fit`、`LineChart` の目盛り） |
| 並べられる数 | 実際に測る。`useFitCount`（高さ・幅に入る数）と `fitSlots`（入らない分を「+N」に）、`AvatarStack` の `fit` |
| 左メニューの形 | 広げた形だけの中身に `data-side="wide"`、畳んだ形だけの中身に `data-side="rail"`。入れ替えのフェードは枠が持つ |

画面の骨組みの区切り（上の「詰める順番」の当てはめ。既定の寸法 `SHELL_SIZES`: 左メニュー 236 / 64px、詳細パネル 380〜320px（主役とパネルに使える幅の 1/3）、余白の下限 8px、主役の最小幅 400px。★ は `shellLayout` の計算で出る幅で、メディアクエリには書かない）。

| 区切り | 段 | 何をするか |
|---|---|---|
| ★ 幅 1405px 未満（使える幅の 1/3 < 380px） | 2 | 詳細パネルを窓に合わせて 380 → 320px へなめらかに詰める（段を付けない。主役に幅を回す。外側の余白は区切りを持たない）。利用者が左メニューを畳んでいれば、空いた幅の分だけ広く保つ |
| ★ 幅 986px 未満（パネルを開くと主役 < 400px） | 4 | 左メニューをアイコンの列に畳む。パネルを閉じていても畳み（引き出しにする前に、まず畳む段を通る。パネルを開いた瞬間に左メニューが縮まない）、覚えている設定は変えない。つまみで広げたら、986px 以上に広がるまで広げたまま・パネルを重ねない |
| 幅 860px 以下 | 4 | ヘッダーの上下の余白を詰め、検索欄を 2 段目に（左メニューは畳んだアイコンの列のまま） |
| ★ 幅 814px 未満（左メニューを畳んでも主役 < 400px） | 5 | 詳細パネルを本体の上に重ねる（`Drawer`）。左メニューは畳んだまま |
| 幅 720px 以下 | 5 | 重ねた詳細パネル（`Drawer`）を、右からでなく下からのシートにする |
| 幅 600px 以下 | 1・3・4・5 | 左メニューを左から出す引き出しにする（スマホだけ。それより広いうちは畳んだアイコンの列を横に置く）。ヘッダーを詰め、メニューと画面名を 1 つのボタンにまとめる。KPI などの帯の中を詰める |
| 高さ 500px 以下の横長 | 1・3・4 | ヘッダーの上下の余白を詰め（段組みの余白は高さで縮む）、検索欄をヘッダーの 1 段目に、KPI の帯を出さない |

- 部品の中身の出し入れにはメディアクエリを使わない（パネルで狭まった枠で外れる）。

#### 操作の結果を見える場所に出す（2026-10-01）

詰める・畳む・重ねると、同じ操作でも結果の見え方が変わる。横に並べた形では見えていた結果が、重ねた形では裏に隠れて「押しても何も起きない」ように見える（スマホで詳細から主役を変える操作を押すと、詳細の裏で主役だけが変わっていた）。
**どの形でも、操作の結果は利用者が見ている場所に出す。** 形ごとに作り分けず、部品が形に合わせて振る舞いを変える。

- **重ねた周りの枠の中から主役を変える操作**（詳細パネルから主役の表示を変える操作・別の画面へ移る操作など）は、操作のあとに `useShell().revealMain()` を呼ぶ。重ねた形（`Drawer`）では詳細を閉じずに画面の下の 1 行（`ShellPanel.peek`。何の詳細か）に畳み、主役をその行の上まで広げて結果を見せる。行を押す・上へ払う・ブラウザで戻ると元の詳細に戻り、× で閉じる。常時表示の詳細（`panel.pinned`）は、重ねる形でははじめから 1 行に畳んで置き、×を出さない（広げたあとも Esc・外側のクリックで 1 行に戻る）。横に並べた形では裏が見えているので何もしない（呼ぶ側は形を気にしない）。
- 詳細の中身だけを変える操作（タブ・詳細の中の別の人へ移る）は呼ばない。閉じると開き直しが手間になるので、主役を見せるために詳細を閉じない。
- 新しい「主役を変える操作」を足したら、狭い幅で押して結果が見えることを確かめる。監査（`reveals`）が、重ねた詳細の中のボタンを 1 つずつ押し、画面の状態（URL のうち詳細の中身以外）が変わったのに詳細が全面のまま残るものを拾う。詳細を開いた画面を足したら `reveals` にも足す。
- 同じ考え方で、形を変えたときは「その形で、操作の結果・現在地・開いているものが見えているか」を確かめる（左メニューの引き出しの中の現在地、畳んだ帯の選択中の値など）。測れるものは監査に足す。

#### 新しい画面・アプリの手順

この手順で組めば、区切りの幅を 1 つも書かずに、Ignite の大きさへの対応（なめらかな余白・周りから詰める・最後に重ねる）になる。

1. **枠は `AppShell` に役割ごとに渡す** — `side`（左メニューの中身。`Brand`・`SideNav` に受け取った `collapsed` を渡す）と `collapse`（畳める・覚える）、`title` と `titleAfter`（範囲の選択など。狭いと詰める）、`search`（ヘッダーの主役）と `tools`（付随する補助。落とす文字に `data-fit="extra"`）、`aux`（補助の帯。低い横長で出さない）、`band`（いつも出す帯）、`children`（主役）、`panel`（詳細パネル）。寸法を変えるときは `sizes` を渡す（区切りは `shellLayout` が計算する）。枠の部品への CSS と、幅の `matchMedia` は書かない（`ignite check` が止める）。
2. **画面の中の帯は `FitBar` に詰める順番を宣言する** — 部品の修飾の組み合わせを詰めていない順に並べる（例: 補足を隠す → 件数を隠す → 2 段目に落として幅いっぱい → 余白 → 短いラベル）。KPI は、まとめた形（「拠点 N」など）を作れるなら `KpiBand`、独立した値なら `.kpis`（折り返す。狭いと縦にそろう）。グラフは `.chart-grid`。
3. **部品を足すときは、詰めた形を修飾で持たせる** — 落としてよい要素に `data-fit="extra"`（ショートカットの手がかりは `"hint"`）、主役に `"main"`。部品の中の出し入れはコンテナクエリ（区切りは全部出したときに要る幅。式をコメントに）。
4. **余白はトークンだけ** — 外側の余白（`--shell-*`）は窓の大きさでなめらかに変わる。部品の中の余白は固定。
5. **確かめる** — アプリの監査（`e2e/ignite.audit.ts`）の `screens` に画面を足す。監査は、スマホの縦（320px）と横向きまでの固定の幅に加えて、操作なしの全画面を開いたまま窓を連続で変え、区切りの前後を含む大きさで、はみ出し・枠に切られた中身・操作の重なりを測る（下限はスマホの縦と横）。アプリ固有の区切りをまたぐ幅は `widths` に載せる。詳細パネルを開く画面は `reveals` にも足す（重ねた形で、主役を変える操作の結果が見えるか）。窓の幅を変えて追従する E2E を 1 本置く。
