# カタログ監査の実行

`npm run audit:design` を使う。Playwrightへの引数も渡せる（例: `npm run audit:design -- --grep DatePicker`）。直接 `playwright test -c catalog/playwright.audit.config.ts` は受け付けない。

## 同じ成功結果の再利用

引数なしの全件監査だけ、保存済みの全追跡ツリー・依存ファイル・Nodeとブラウザ一式・OSと端末・利用可能な書体・実行環境が一致すれば、24時間以内の成功を再利用する。保存先は共通Gitディレクトリの `devboard/ignite-audit-cache-v1/`。結果のレポートと画像はハッシュ照合後に復元し、再利用したことを出力する。起動元の実行識別子・通信先など、監査に使わない既知の情報は照合から除く。未知の変数や描画設定は照合し、環境変数の生値は保存しない。

未コミット変更・未追跡ファイル・想定外の入れ子の `node_modules`・外部参照・照合不能な環境（macOS以外も含む）では再利用せず測る。引数付き実行と `IGNITE_STEPPER_SCREENSHOT` 指定時も再利用・保存しない。単体・型・ビルド・配布の通し確認は毎回実行する。

`IGNITE_AUDIT_FRESH=1 npm run audit:design` で測り直せる。同じ入力の再確認はOSの入力別ロックで待ち合わせ、開始時に旧成功を失効する。子群の停止と共通監査ロックの解放が成功してから新しい結果を公開する。捕捉可能な中断では公開済み結果も失効する。SIGKILLに対しては成功結果のatomic renameが確定点となる。破損・期限切れ・復元失敗も再実行へ戻す。

画面開始時と幅変更後は、書体の準備後、有限アニメーションがないことを2フレーム確認する。無限アニメーションは待たない。全体で10秒を超えたら測定に進まず失敗する。後から取得するデータやタイマーによる更新は `open` / `act` で明示的に待つ。ホバー・押下・状態比較・詳細操作の待機は維持する。カタログの時計を固定し、実行日で文字幅・カレンダーが変わらないようにする。部品確認・タッチ監査も外部取得を固定し、端末の書体で測定する（通常表示のカタログは変更しない）。

## 監査の排他と終了

監査用5198は `/tmp/ignite-catalog-audit-5198.lock` の共通ロックでworktree間を直列化する。全監査は約18分かかり、並行するタスクの監査が何件も並ぶことがある。そのため待機の上限は、同じ所有者がロックを30分を超えて保持した場合とし、所有者が入れ替わる（順番が進む）たびに数え直す。待機全体は最大3時間で打ち切る。待っている間は1分ごとに待機の秒数とロックの所有者を出力する（出力が止まると、取り込み前の確認などの呼び出し元に固まったと見なされて止められるため）。Viteの待受開始は最大60秒待つ。Vite自身の待受成功通知後に、そのworktreeのPlaywrightを実行する。成功・失敗・INT/TERM/HUPで、自分が起動したPlaywrightとViteのプロセス群を終了し、停止確認後にロックを解放する。停止できなければロックを残して失敗を返す。生存照会が権限エラーになった場合も終了とは見なさず、有限の停止待ちで消滅を確認できた場合だけ解放する。

既に5198が使われている場合は、既存サーバーを停止・流用せず失敗する。古い監査コマンドはこのロックを使わないため、所有元の監査を終了してから再実行する。

SIGKILL、OS停止など終了処理が走らない場合はサーバーやロックが残りうる。次回は所有PIDが終了した残骸を検出して失敗する。所有情報が欠けている場合やPIDが再利用された場合も、所有者が変わらなければ30分で打ち切る。`owner.json` のPID・worktreeと5198の所有元を確認し、所有元でプロセスを終了してからロックを手動で除去する。他者のプロセスをkillしたり、所有確認なしでロックを消したりしない。

通常表示のDevBoardショートカットは従来の `http://localhost:5199` と `bash scripts/start-catalog.sh` を使う。監査ロックとは独立しており、この修正ではWebDockへ移行しない。
