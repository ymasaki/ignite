# カタログ監査の実行

`npm run audit:design` を使う。Playwrightへの引数も渡せる（例: `npm run audit:design -- --grep DatePicker`）。直接 `playwright test -c catalog/playwright.audit.config.ts` は受け付けない。

通常の検査は Playwright の既定のヘッドレス Chromium で実行し、画面やフォーカスを使わない。オーナーの操作を妨げないよう、この Mac での自動検査に `--headed`・`--ui` は使わない。グラフの吹き出しの回帰確認だけなら `npm run audit:design -- --grep グラフ共通` を使う。

## 並列の測定と判定

測定は6 worker（`IGNITE_AUDIT_WORKERS` で変更）に分け、判定「決まりから外れたところがない」は測定がすべて終わってから別のプロジェクトで行う（[並列で動かす設定](adopting.md#監査を並列で動かす1100以降)と同じ）。各テストの指摘は `catalog/test-results-audit/artifacts/.ignite-audit/` に記録し、テストを定義した順に集計するので、レポートと画像の番号は worker の数や終わった順で変わらない。前回の画像とレポートは、実行で最初に始まったテストが一度だけ消す。判定を含めない一部の実行（`--grep DatePicker` など）でも、worker の終わりにレポートを書く。判定を `--grep` で選ぶと、測定はすべて動く。

## 同じ成功結果の再利用

引数なしの全件監査だけ、保存済みの全追跡ツリー・依存ファイル・Nodeと使用版のブラウザ一式・OSと端末・利用可能な書体・実行環境が一致すれば、24時間以内の成功を再利用する。保存先は共通Gitディレクトリの `devboard/ignite-audit-cache-v1/`。結果のレポートと画像はハッシュ照合後に復元し、再利用したことを出力する。起動元の実行識別子・通信先など、監査に使わない既知の情報と、単体テストの変換キャッシュ（`node_modules/.vitest-cache`）は照合から除く。未知の変数や描画設定は照合し、環境変数の生値は保存しない。依存・ブラウザ・成果物のファイル群では、列挙順・権限・リンク先・全バイトのSHA256を保ったまま、ハッシュの読み取りだけを最大4個まで並行にする。1件でも読み取りに失敗したら、ほかの読み取りの終了も待ち、部分的な照合結果は使わない。

未コミット変更・生成先以外の未追跡/ignoredファイル・assume-unchanged/skip-worktree・想定外の入れ子の `node_modules`・外部参照・照合不能な環境（macOS以外も含む）では再利用せず測る。引数付き実行と `IGNITE_STEPPER_SCREENSHOT` 指定時も再利用・保存しない。単体・型・ビルド・配布の通し確認は毎回実行する。

`IGNITE_AUDIT_FRESH=1 npm run audit:design` で測り直せる。同じ入力の再確認はOSの入力別ロックで待ち合わせ、開始時に旧成功を失効する。入力待ちも1分ごとに出力し、待機秒数を計測する。子群の停止と共通監査ロックの解放が成功してから新しい結果を公開する。捕捉可能な中断では公開済み結果も失効する。SIGKILLに対しては成功結果のatomic renameが確定点となる。破損・期限切れ・復元失敗も再実行へ戻す。

保存先は入力と環境の組み合わせごとに増えるので、監査を始めるたびに、24時間を過ぎた成功結果・保存途中の残り・成功結果のない古いロック（ほかの監査が保持していないもの）を消す。再利用が当たらなかったときは、同じソースの直近の成功と違った条件（`environment`・`dependencies`・`browsers` など）を出力する。

画面開始時と幅変更後は、書体の準備後、有限アニメーションがないことを2フレーム確認する。無限アニメーションは待たない。全体で10秒を超えたら測定に進まず失敗する。後から取得するデータやタイマーによる更新は `open` / `act` で明示的に待つ。ホバー・押下・状態比較・詳細操作の待機は維持する。カタログの時計を固定し、実行日で文字幅・カレンダーが変わらないようにする。部品確認・タッチ監査も外部取得を固定し、端末の書体で測定する（通常表示のカタログは変更しない）。そのため、Web 書体が遅れて届いて端末の書体から差し替わる場面は画面監査では起きない。書体に依る寸法（`ch` など）はこの差し替えで変わるので、その場面は部品確認（`parts.e2e.ts` の「書体が差し替わった直後」）で書体を切り替えて確かめる。

## 監査の排他と終了

監査サーバーは実行ごとに OS が空きポートを選び、待受成功時に実際のポートを親へ通知する。監査全体は `/tmp/ignite-catalog-audit-5198.lock` の共通ロックでworktree間を直列化する。ロック名の5198は旧版との互換のために残した名前で、待受ポートではない。全監査は約3分（1.9.0までの直列では約15分）かかり、並行するタスクの監査が何件も並ぶことがある。そのため待機の上限は、同じ所有者がロックを30分を超えて保持した場合とし、所有者が入れ替わる（順番が進む）たびに数え直す。待機全体は最大3時間で打ち切る。待っている間は1分ごとに待機の秒数とロックの所有者を出力する（出力が止まると、取り込み前の確認などの呼び出し元に固まったと見なされて止められるため）。Viteの待受開始は最大60秒待つ。Vite自身の待受成功通知後に、そのworktreeのPlaywrightを実行する。成功・失敗・INT/TERM/HUPで、自分が起動したPlaywrightとViteのプロセス群を終了し、停止確認後にロックを解放する。停止できなければロックを残して失敗を返す。生存照会が権限エラーになった場合も終了とは見なさず、有限の停止待ちで消滅を確認できた場合だけ解放する。

既存サーバーを停止・流用せず、自分が起動したサーバーの通知だけを待つ。監査の起動や通知が失敗した場合は、別のサーバーを測らず失敗する。

SIGKILL、OS停止など終了処理が走らない場合はサーバーやロックが残りうる。次回は所有PIDが終了した残骸を検出して失敗する。所有情報が欠けている場合やPIDが再利用された場合も、所有者が変わらなければ30分で打ち切る。`owner.json` のPID・worktreeと、その実行が起動した監査サーバーの所有元を確認し、所有元でプロセスを終了してからロックを手動で除去する。他者のプロセスをkillしたり、所有確認なしでロックを消したりしない。

通常表示のカタログは監査用サーバー・ロックとは独立する。起動・専用ポート・worktree の一時確認は [カタログの運用](releasing.md#ステージングとプロダクション) を参照する。
